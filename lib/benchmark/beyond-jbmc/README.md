## Comparator and adjudication policy

Use the Ubuntu 24.04 JBMC 6.11.0 binary with its own packaged Java models for the primary stock column. Use its packaged string refinement, runtime exceptions and unwinding assertions, unless a case explicitly prespecifies a different exception property. For a matched comparison, give both engines the same input construction, entry guard, observations and distinct version bindings. Record any different object-factory assumptions alongside the stock result. A second named stock profile may use the exact class bytes bound by the subject's JDK for a documented model discrepancy. Bind those bytes and the scope before measuring that profile. Compare with the union of qualified comparator decisions.

Retain the literal assertion ID, status, post-call false control, unwind failures and the invocation of each standalone run. An unreachable or missing target, a failed unwinding assertion, or a difference in the input universe prevents matched proof credit. A counterexample earns credit when the original JVM reproduces the named observation on that input. A decision contradicted by the JVM, bytecode or an independent specification stays visible as a wrong decision. Keep unresolved disagreements, timeouts and unsupported rows in the denominator. ## Blind draw

The sampling frame is the signed Ubuntu Universe Java library population on the base 22.04, 24.04 and 26.04 LTS releases. The two adjacent LTS intervals provide distribution-published binary JARs with an exact source-package provenance. Upstream Maven binaries can differ from these builds. The inference applies to this release population. [Ubuntu archive](https://archive.ubuntu.com/ubuntu/dists/)

The draw uses one private seed. It orders eligible entries by artifact and version, ranks projects and pairs with the seed, reserves four positions in each specified stratum, and takes at most one pair per project and source package. Its first pass prefers adjacent numeric releases. Source or binary release notes supply documented change evidence. Eligibility requires a common public method with an executable body in two different JARs. Public package descriptions set the strata before either checker runs. The archive indexes, screening record, primary artifacts and seed accompany the sealed manifest. Candidate names and reference materials stay in the owner-only directory `~/.cache/in-the-loop/beyond-jbmc/panel`. [Selection program](seal_panel.py) · [Manifest commitment](panel.sha256)

At freeze, verify the commitment before opening the manifest. Use the original artifact digests and ordered dependencies for the automatic run. Record each independent primary question and its preservation control before reading checker output. Keep the references and labels out of the automatic workflow. A missing dependency or unreachable caller counts in the original 16. The routine-upgrade preference uses numeric adjacency as its selection rule. Check published release history before claiming upstream releases were consecutive.
