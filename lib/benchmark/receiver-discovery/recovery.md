# Receiver recovery on the original public callers

The original Commons Configuration predicates for JSON #565 and YAML #601 each returned false on both dependency sides when the standard system properties table contained an invalid default lookup name. Each predicate catches the initialization failure during public construction and returns false before either document parser reads its input. With the library setting absent from the stock table, the same predicates returned true for each of the four registered selectors. Each physical run starts a fresh, single-threaded Temurin 21.0.13 JVM with the original dependency bytes in their frozen order. The strict checker assumes that the JDK classes initialized successfully. Both routes execute the original application initializer.
