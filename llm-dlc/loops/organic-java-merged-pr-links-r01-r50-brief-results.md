## Reproduction and scope

Each example contains its caller, all three predictions and falsifiers, the ordered and hashed classpaths, and both observed outcomes. The same compiled caller runs on the parent and landing in a separate JVM for each history. The offline audit checks the registrations against the brief. Its `--replay` option also recompiles the callers, checks class origins and compares all observations. Run `python3 verification/merged-pr-links/audit.py --campaign r01-r50` for the offline check.

Forty-eight cases use complete pinned module builds. R39 places each original Parquet dictionary reader ahead of the same 1.18.2 release graph. R42 places the two original Reactor operator implementations ahead of 3.1.1.RELEASE. Their complete class inventories are checked at replay. R16 uses a source-reconstructed Commons IO snapshot, R18 a reconstructed parent POM, and R28–R30 use the timestamped Jackson inputs in their runtime locks. R35 ran on a little-endian host. [Build provenance and limitations](organic-java-merged-pr-links-r01-r50-brief-setup.md)

The Commons IO and Avro discrepancies and the observable boundaries in Resilience4j and AssertJ are recorded for review. [Upstream findings](../../verification/merged-pr-links/r01-r50/upstream.md)

The physical record includes every parent history. Eighty-nine have a separate machine-readable parent prediction and all 89 matched. The other 61 retain the measured return or exception alongside the brief’s text. The independent replay reproduced all 312 observations and a byte-identical audit. The debugger also verified 32 original-method trials across the marked reader, Observable groups, result-based retry and record accessor. All selected outcomes agreed with their ordinary public callers. ## Published releases and additional public histories

The original caller bytecode ran on 44 published deployments across 22 cases. Of the 132 release observations, 131 matched the designated parent or landing exactly. The one version-specific difference was Resilience4j 2.1.0. A retryable result at a negative interval produced no retry event there. Both PR pins and 2.2.0 reported a −1 ms retry despite making just one supplier call. The release checker records this exception explicitly. [Versions and historical sides](../../verification/merged-pr-links/r01-r50/release-references.json) · [Runtime digests and observations](../../verification/merged-pr-links/r01-r50/release-observations.json)

H2 2.2.224 reproduced the null aggregate and 2.3.230 returned the bindings. On Temurin 8u512, Reactor 3.1.0.RELEASE and 3.1.1.RELEASE stopped before the trailing values, while 3.1.2.RELEASE delivered both. The HTTP 400 fallback reproduced the access failure on Resilience4j 2.1.0 and returned a fresh application lambda on 2.2.0. JUnit 6.1.1 ran both dynamic leaves but failed their suite, while 6.1.2 reported the suite success. JUnit Jupiter 5.12.1 kept the passing sibling’s directory after the earlier failure and 5.12.2 removed it. Published Parquet 1.18.1 and 1.18.2 also reproduced all six observations from the two compiled reader overlays. Four additional callers made 42 observations across pins and releases. Commons Collections 4.6.0 matched the merge on all three unique-index histories.
