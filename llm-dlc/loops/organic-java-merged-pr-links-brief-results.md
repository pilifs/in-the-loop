# Merged Java changes at the public API

All 20 merged revisions met their intent prediction. All 20 unchanged controls matched on both sides. Four of the 20 challenge predictions were refuted on the merged code. The additional Woodstox diagnostic matched on the merge. In total, 57 of the 61 merged-revision predictions held on these inputs. The follow-up classified all four refuted predictions. Avro, ical4j and jOOλ have confirmed upstream defects. The Jackson CSV challenge used the wrong iterator configuration for a sequence of row arrays. Each classification uses the original compiled caller, a public contract and later release and development builds. The three reports are ready for the user. ## Where the merged behavior disagreed

- **Jackson CSV #625.** With the quoted records `"te,st"` and `"x""y"`, both lookaheads succeeded for the first row. On the merge both then reported exhaustion before the second row. The parent advertised the second row and threw `MismatchedInputException` when it was consumed. [Iterator history](../../examples/409-jackson-csv-end-of-input/observations.json)
- **Avro #3709.** Both branches preserved the declared presence of the default. Putting the array branch first produced the list and IDL initializer `[1]`. Putting the scalar branch first made both `defaultVal()` and the IDL writer throw `AvroRuntimeException` on both pins. [Field and writer readback](../../examples/411-avro-idl-union-default/observations.json)
- **ical4j #931.** The fix returned both moved occurrences for input order B,A. For A,B it returned only B. The two overrides name different recurrence IDs but A’s replacement starts at B’s original instant. [Typed periods, durations and recurrence IDs](../../examples/412-ical4j-moved-occurrences/observations.json)
- **jOOλ #418.** On the third row in both module variants, `[-5,5]` returned endpoints 1 and 3. Widening only the upper bound to `Long.MAX_VALUE - 1` returned 1 and 1. [Both module histories](../../examples/419-jool-window-endpoints/observations.json)

## Reproduction and scope

Run `python3 examples/tools/build.py --plan 419` to see the registered questions and deployments. With the setup cache present, `python3 examples/tools/build.py 419` rebuilds the caller once per deployment pair, verifies the JDK release fingerprint and every ordered JAR digest, and checks the recorded outcomes in new JVMs. Each trial verifies the supplying JAR for its registered original classes. The reports describe only the stated finite inputs. [Replay implementation](../../examples/tools/targets/public_comparison.py)

Run `python3 verification/merged-pr-links/audit.py` to validate the 61 question identities and predictions against the original brief, the upstream pins against the comparison links, the primary artifacts against the setup digests, and every recorded decision against the typed result. The audit works without the setup cache. The `--replay` option also repeats every physical trial. [Campaign audit](../../verification/merged-pr-links/audit.py)

The Solr pin-built core could not start on the release support classpath because the required SolrJ method was absent. The working comparison used the exact facet sources from the two pins over the same 9.8.0 runtime, with the same schema, /update handler, /select handler and JSON writer. On JDT, using the fully unsigned core caused a split-package signer mismatch with ECJ before formatting. Both public factory calls ran with the changed package over the original signed 3.47.0 support graph. A full Tycho build would require the matching Eclipse p2 target platform and OSGi test runtime. Jackson CSV uses each pin’s CSV sources and released 3.2.0 dependencies.
