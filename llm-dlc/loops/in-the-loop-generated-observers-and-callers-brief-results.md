# Generating public Java callers from registered predictions

The product produced a repeatable public observation on both original deployments for all 31 registered questions across 13 cases. The finite evaluator established 26, refuted three and left two open because the original parent contradicted its registered baseline. Those two have complete JVM observations. The campaign covered 45 registered input histories, each executed on both releases in fresh JVMs. [Per-question scorecard](../../verification/generated-observers/scorecard.json)

## Qualification and authorship

Stage 3 compiles one caller against the older public API. The runnable bundle retains the Java source, class archive, fixture bytes or input recipe, signed artifact identities, effective JDK, selected signatures, field mapping, scope and evaluator predicates. All 13 cases used the same class bytes on the two deployments. An offline evaluation can read the original field values from the receipt and score a new prediction. The stricter public JVM replay still requires the selected original method and its provider. [Runtime workflow](../runtime.md#stage-3-set-the-examples-up)

Changing only Spring's fixed-side expectation to 126 refuted the new prediction while preserving the raw observation digest. Independently changing the production subject made the same compiled observer actually return Integer 126 and BigInteger 126. A caller returning a constant after the real invocation lost numeric correspondence. A fixture throwing the expected exception before entry and a graph caller reading a fresh receiver both lost qualification despite matching output values. Replacing either a registered fixture or its archived bytes also failed the digest check. [Numeric, subject, fixture and startup controls](../../verification/generated-observers/receipts/458-controls.zip) · [Receiver-identity control](../../verification/generated-observers/receipts/J16-controls.zip)

In a separate fresh setup, the evaluator already expected 126 before Java generation began. The source, input registration and compiled class archive matched the correct setup byte-for-byte. The public replay preserved the incorrect prediction and refuted it with both fixed 127 returns. [Wrong prediction from setup through replay](../../verification/generated-observers/receipts/458-wrong-at-setup.zip)

One case requested a checked helper, covering two questions. The product observed six distinct argument pairs at actual `Math.min(II)I` calls from the public stream read and computed expected results with an independent minimum. Both old/new question pairs qualified through closed integral bytecode and exhaustive evaluation of those rows. Across the repeated original JVMs, the rewind question used 14 parent and 20 fixed substitutions. The preservation question used ten on each release. Withholding one used row opened only the dependent question. A wrong result, wrong class binding and missing marked consumption invalidated both derivations. The ordinary public observations continued to hold. The strict native helper query returned unverifiable. [Generated table, checked applications and falsifiers](../../verification/generated-observers/receipts/io-helper.zip)

Additional debugger traces located changes reached later in the same history. The stream observer entered `reset()` on both releases. The filtered Lucene search reached seven changed methods on the parent and eight on the fix, including the fix's `hasChildWithMissingValue()`. On both Spring releases the event reader's `buildEvent` ran below `Flux.blockLast` on the registered subscription stack, after `bodyToFlux` returned. That establishes reach for these invocations. Detached callbacks on another thread still need a way to identify the originating subscription. One preliminary comparison rejected Lucene's fresh hidden-lambda addresses. The corrected comparison retains every raw frame and ignores only that VM-assigned address. The deterministic generator ran under a filesystem allow list. The operator could read the reviewed meanings, shared producer implementation, pinned production JARs and JDK. A read of an evaluator-only marker had to fail before generation began. The independent evaluator retained historical Java, upstream tests, helper tables, predictions and recorded outcomes. It compared the final typed fields with the historical authored observations at their registered scope. The full map snapshots also had an independent JDK comparison.

Kryo's first development scaffold stopped before Java emission. A JDK 8 dependency had a JAR index. Its only provider was its own deployed filename. Reading the original index allowed the shared resolver to qualify that case while preserving the open result for renamed or multi-provider indexes. [Initial setup record and original index bytes](../../verification/generated-observers/receipts/J10-initial-index.zip)

The campaign supplied semantic inputs and wrote the maintained Java-emitting recipes. The scorecard counts that engineering as assistance and records it separately from operator edits. At setup, no person or campaign agent edited a generated caller, manifest or scope. The three post-freeze recoveries required new product recipes. The numbered Spring and Vavr setups can also read the existing registrations directly. Vavr needs one additional fixture fact, the counting supplier's return value of 99. The remaining domain packets use curated semantic input data. No model synthesis or fresh project draw was used.

Cold, warm and independent empty-cache comparisons agreed for every final question. Of 62 question sides, the warm run reused 44 exact positive receipts and executed 18 sides again. One initial job stopped before measurement because the checker was outside the runner's checkout. The corrected command used the checker built for that job. Another job passed all eight development repeats but declared a wildcard as its output path. Two successful repeats listed the eight archives explicitly, and their collected bytes supply the scorecard. [Job receipts and output digests](../../verification/generated-observers/collector.json)

The smallest additional caller that stayed open was Spring's three-argument `NumberUtils.parseNumber(String, Class, NumberFormat)`. Both original JARs expose it. For the fully specified input `1,5`, setup needs to construct a DecimalFormat with pattern `0.0` and German decimal symbols, enable BigDecimal parsing, and pass that object as the third argument. The numeric generator accepts the two-argument input and stops before emitting Java for this one. ## Reproduction

The following command exercises the scaffold-only boundary for examples 458 and 445 in a fresh checkout containing their existing registrations and pinned runtime manifests. It keeps the checkout for a later resume. Use the same checker binary for the subsequent build.

```sh
export JVMCONTRACT="$PWD/lib/target/release/jvmcontract"
work="$TMPDIR/public-observer-demo"
python3 verification/generated-observers/numbered_handoff.py --scaffold-only --work "$work" 458 445
python3 "$work/examples/tools/build.py" 458
python3 "$work/examples/tools/build.py" 445
python3 llm-dlc/tools/watch.py --root "$work" preflight 458 445
python3 verification/generated-observers/scorecard.py --check
python3 verification/generated-observers/scorecard.py --question filtered-child-hypothesis
```

The recorded handoff classified both examples as prepared before resume and decided afterward. Source, compiled archive and generation-record hashes and modification times held across the numbered executions. The original authored comparison remains available through its explicit authored route. [Numbered handoff, plans and receipts](../../verification/generated-observers/receipts/numbered-handoff.zip) · [Collector revisions and output digests](../../verification/generated-observers/collector.json)

The collector recorded 16 jobs. Fourteen passed. The initial checker-location failure and the first literal hidden-lambda comparison have passing replacements. The final changed-method comparison is recorded at collector revision `90692aac0ce2`. All 55 suites selected for the final evidence passed.
