## Reproduction and scope

From the repository root, run the native recovery command on a registered single-revision strict property. It executes the original command, derives a recording request from the first initializer diagnostic, and retries the frozen property. The watcher reports the original result alongside the scoped one. A resumed literal-encoding proof can reuse a qualified trace after rechecking the current class, field, full input and effective profile on a fresh JVM. The solver runs again. The application never receives an expected public output. [Workflow and example commands](../../lib/README.md#proof-output) · [Watcher setup instructions](../runtime.md#stage-3-set-the-examples-up)

The shared recorder and importer contain the Java and JDK operation rules. The campaign supplied the public entries, reviewed predicates, pinned classpaths, locale profiles, original historical callers and labelled experimental fixtures. The charset, reflective and live-table diagnostic requests were derived from the original verifier output. Batik's getter, setter and replaced JAR and the file parser inputs were explicitly constructed evaluation histories. Public table receipts retain hashes, counts and operation sites. [Campaign sources](../../lib/benchmark/startup-facts)

## Premises and falsifiers

The two-profile symbolic exercise quantified a Boolean selecting UTF-8 or US-ASCII. The explicit UTF-8 operation returned two for both selections. The selector-based operation returned one for ASCII and two for UTF-8. Both native proofs ran without a startup premise. For the original defaulted `String.getBytes()`, the separate receipt established which selection the JVM actually used at the original instruction. The one-byte original witness refutes the two-byte prediction over the registered pair of profiles. [Native profile checks](../../verification/startup-facts/startup-controls.zip)

A receipt from the other Commons IO release failed admission. So did a receipt for a different logical revision with identical class bytes. The subject identified its application loader and platform parent. The importer binds the ordered paths and their contents, the JDK image, recorder and effect rules, launch and observation boundary. [Revision and loader controls](../../verification/startup-facts/deployment-bindings.zip)

All six previous setting countermodels kept their named refusal with the relevant premise withheld. The ordered joint fixture produced 7 for Root then Reader and 0 for Reader then Root, with distinct assumption identities. The opaque StringBuilder read and concurrent application initialization were refused. Killing the capture after one completed root produced zero reusable recordings. A fresh retry in the interrupted work directory succeeded. [Setting, order and interruption evidence](../../verification/startup-facts/startup-controls.zip)

On each Batik deployment, substituting the later identical provider, a different defining loader, a wrong digest of the bytes consumed, or a different decoder failed admission. The archived charset qualification performs the following normal and resumed workflow from a clean checkout. It compiles the existing fixture and compares both watcher reports with fresh original JVMs. With the registered JDK selected through `JAVA_HOME`, these commands reproduce the ASCII witness. [Full reproduction driver](../../lib/benchmark/startup-facts/charset.py)

```bash
work="$TMPDIR/startup-encoded"
mkdir -p "$work/classes"
"$JAVA_HOME/bin/javac" -proc:none -g -encoding UTF-8 -d "$work/classes" lib/tests/fixtures/setting-countermodels/sc/*.java
claim=(lib/target/release/jvmcontract prove 'sc.M#encoded()I' --classes "$work/classes" --assert 'result == 2' --engine native --gaps strict --json)
python3 examples/tools/targets/startup_facts.py --work "$work/run" --revision fixture-v1 --locale C -- "${claim[@]}"
python3 llm-dlc/tools/watch.py startup-facts "$work/run/startup-report.json"
python3 examples/tools/targets/startup_facts.py --resume --work "$work/run" --revision fixture-v1 --locale C -- "${claim[@]}"
python3 llm-dlc/tools/watch.py startup-facts "$work/run/startup-report.json"
python3 verification/startup-facts/startup_scorecard.py --check
```
