# Twenty organic Java product changes

All twenty disclosed PRs reached their public observer on both registered deployments. **Nineteen reproduced a difference. Eclipse Collections qualified as preservation across its collision-removal domain.** The frozen application verifier decided all 43 questions over 85 histories. It established 42 and refuted the proposed Lucene filtered-child preservation property. All 85 histories have independent physical JVM observations. [Audited decisions and timings](../../verification/product-behaviour/audit.json)

The first jsoup run used the existing frozen verifier. Zip4j and all subsequent cases used the same implementation. Each public claim retained its original caller, ordered production providers, environment, two fresh JVM qualifications per input and side, typed observations, and a receipt. Case authorship required zero user-written harnesses or credentials. The study supplied the observers and scopes, including the two-domain calendars, disk databases, archive readers, and local protobuf receiver. The setup run supplied the source and binaries. ## What the counts measure

The two independent executions of every input on each original deployment confirmed **340 original method entries** in the cold comparisons. A history can contain many more operations. J17 alone executes two removals on each of 127 subsets per insertion order. The 170 original, uninstrumented JVM histories are counted separately. The setup preflights and upstream CI tests contribute zero to these figures. [Per-case registrations and measurements](../../verification/product-behaviour/audit.json)

Exact repeats reused **65 of 86** public claim sides and performed 68 fresh qualified entries. Cold, warm and clean took 661.5, 258.0 and 636.8 summed seconds across cases. Replacing the repaired product artifacts with genuine parent bytes at the same filesystem paths caused 170 fresh entries. Every resumed result, witness and input scope matched an independently empty cache. The separate original-client-on-new-runtime comparisons used another 170 fresh entries cold and 170 clean. All 344 receipt references were checked against their archived bytes and the public evidence composer. [Job records and output checksums](../../verification/product-behaviour/jobs.json) · [Independent receipt audit](../../verification/product-behaviour/audit.py)

Thirteen cases used complete pinned production modules or the rebuilt Linux JNI deployment. POI used its pinned OOXML module over the recorded support graph. Calcite used the pinned core and linq4j modules after its setup job passed. The linq4j archive occupies the same slot as the reactor output it replaces. J04, J08, J15, J16, J18, J19 and J20 used exact changed production classes over the named release graphs. Each case’s `bindings.json` records both upstream commits and trees, production source selection, ordered artifact digests and JDK release. The public conclusions have the scope of those deployments. ## Boundaries exposed by the public calls

- The reused Parquet page writer and the closed file produced different answers to the transfer question. The first retained stale data after fallback. The file writer creates a fresh column store at a row-group boundary. Independent page and row readers verified every dictionary entry and decoded value in the second group. Spring Batch took its saved state across the opposite boundary. Shutting down HSQLDB, rebuilding the JDBC repository and opening a new reader carried the wrong or right offset into the next two rows. [Parquet scope](../../verification/product-behaviour/cases/J08/case.json) · [Spring Batch scope](../../verification/product-behaviour/cases/J15/case.json)
- Lucene’s filter selected three value-bearing children. The fixed comparator still inferred a missing child from the entire parent block length. A retained public witness records A/null even after the filter excluded that child. The initial preservation prediction is still present and refuted. A follow-up held the sole selected child at 30. The fix returned 30 with no excluded child and null with an excluded child, even when that excluded child had a real value of 05. The parent returned 30 in all three controls. [Original prediction and witness](../../verification/product-behaviour/results/J14/first/summary.json) · [One-parent controls](../../verification/product-behaviour/results/transfer-controls.json)
- Seven cases retain an overlay boundary. To measure whether that boundary affects an observation, the first low-cost comparison is J04’s already buildable recurrence module on one US default and its explicit-Monday control. J08’s full upstream build needs Thrift 0.23.0. The setup records Spring repository responses for J15, J18 and J20 and unavailable publishing dependencies for J19. These affect full upstream builds. The measured product graphs ran from the local cache. SQLite’s native conclusion covers the measured Linux x86-64 libraries. ## Reproduction

Each case directory contains its observer, machine-readable prediction, ordered bindings and independent physical results. From the repository root, `python3 -B verification/product-behaviour/register.py physical J02` checks the jsoup observer against both prepared deployments. The application jobs invoke `qualify.py` through the verification pipeline. Each original `plans.zip` holds the five complete plans, the materialized registration and all receipts. The case-specific experiments use separate outputs. [Public plan runner](../../verification/product-behaviour/qualify.py) · [Campaign registration](../../verification/product-behaviour/register.py)

Run `python3 -B verification/product-behaviour/audit.py` to check the committed evidence. The audit recomposes original typed observations, verifies archive and receipt digests, and compares warm and replacement outcomes with their clean counterparts. [Evidence index](../../verification/product-behaviour/audit.json)
