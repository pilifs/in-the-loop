# Second unfamiliar Java upgrade panel

The draw selected 16 projects, four per stratum, from 85 eligible release pairs. The public digest was recorded before reference investigation. All 32 selected JARs and all 32 upstream source archives match their signed Ubuntu indexes. Five of 21 screened pairs lacked a common executable API. The frozen product was recovered byte for byte, including the earlier version of the resource selector's class inventory. [Selection](selection.json) · [Draw, seed, exclusions and signed index identities](draw)

Each reference has a public consumer compiled against the older release, a primary observation, an unchanged control and source evidence. An independent Java oracle gives the expected observations. The same consumer classfile runs in four fresh JVMs, under each original release's application loader and a resource-recording loader. The receipts give the defining providers, consumed resources, returned values, failure stage and any earlier unsuccessful attempt. The deployment manifests record signed dependencies missing from the local cache. The measured classpaths are the ones recorded there. Thirteen callers passed on both releases. Eleven of their 38 sampled primary observations changed across eight projects, and all 38 controls held. A JVM sample establishes only the listed inputs. The original 16-project discovery score and the historical 187 remain separate populations.

Only callers passing all four original JVM launches enter verification. The automatic operators receive only the neutral binary deployment, the JDK and their frozen implementation. The matched comparison gives all engines the same old and new original-deployment predicates. Their conjunction is the registered pair question. Each side has an inverse and stock JBMC has its post-call false control. A draw with outstanding jobs or scaffolding stops retains the full denominator.
